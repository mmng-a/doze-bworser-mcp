# doze-bworser-mcp

[English](README.md) | [日本語](README.ja.md)

この開発ブランチはElectron構成です。配布済みの0.2.0は従来のChrome構成で、以下の新しい共同操作画面は未リリースです。

Codexの複数スレッドで専用のElectronを共有するローカルMCPです。別タブは並行し、同じタブの操作は順番に実行します。各呼び出しは完了を待ちます。JavaScriptダイアログで中断した場合は、元の操作を繰り返さず `handle_dialog` で応答してください。

## 構成

| 要素 | 役割 | 動作期間 |
| --- | --- | --- |
| Rustの標準入出力ランチャー | 共有サービスの起動・接続、認証、データの中継 | MCP接続ごとに1個 |
| 共有のRust監視プロセス | OSのファイルロックを保持してNodeの終了を待つ | サービスの起動中に1個 |
| 共有のNode | 公式MCP SDK、Puppeteer、所有者、順序、取消の管理 | 最後の接続が閉じて短い後始末の待機が終わるまで |
| プロジェクトごとの専用Electron | ページの表示と操作、保存済みのログイン状態の利用 | そのプロジェクトの最初の `open_page` から最後のタブ終了まで |

Codexは標準入出力のMCPとしてRustを起動します。RustとNodeの間は、macOS・LinuxではUnixドメインソケット、Windowsでは名前付きパイプを使います。RustはMCPを解釈せず、内部用のブラウザ操作RPCも持ちません。MCPを処理するのはNodeだけです。接続開始時にHMAC-SHA256で相互認証し、資格情報そのものは送信しません。Unixソケットは専用の非公開ディレクトリに置きます。小さな認証メッセージで、MCPのストリームか、状態確認の処理かを選びます。MCP用のTCP待受、HTTP MCPの中継、ログイン時の常駐サービスは使いません。

Git管理下では作業ツリーのルートごと、Git管理外では作業フォルダごとに専用のElectronと永続プロファイルを使います。同じ保存領域を使うスレッドはCookie等を共有し、担当ごとにページを所有します。ページは通常非表示で動き、明示した共同操作だけ表示します。表示切替でページを作り直さず、別ページの作業も続けられます。クリック・入力・アクセシビリティ情報の取得はPuppeteer-coreの公開APIを利用します。

## 共同操作

`open_page` の `headed: true`、または既存ページへの `show_page` で表示します。同じ担当・保存領域のページを、1つのウインドウのタブで表示します。戻る・進む・再読み込みとタブを高さ48pxの1行にまとめ、選択中のタブだけページ名とドメインを表示します。タブを選んだ状態でクリックするか、⌘L（LinuxではCtrl+L）を押すと、その場所がURL入力欄に変わります。他のタブはfaviconで表示し、収まらない分は「⋯」から選択できます。

ショートカットはElectronのメニューアクセラレータで登録します。macOSのメニューはアプリ・ファイル・編集・表示・履歴・ウインドウで構成し、編集には標準のUndo／Redo、切り取り、コピー、貼り付け、書式なし貼り付け、すべて選択などを含みます。Linuxではメニューバーは通常隠し、Altキーで表示します。

操作画面はOSのライト／ダーク設定に追従する白黒の配色です。非アクティブなタブも背景色と枠線で区別します。

右端の鉛筆ボタンで注釈モードを開きます。ポインター下の要素を枠線とタグ名で確認し、クリック、またはドラッグで範囲を選び、選択箇所の近くに開く欄にコメントを入力して保存できます。⌘Enter（LinuxではCtrl+Enter）でも保存できます。注釈中はツールバーの配色と「注釈中」の表示が変わります。そこにポインターを合わせると保存済みの注釈一覧を開けます。保存した注釈は番号付きのピンで表示し、ピンにポインターを合わせるとコメントを確認できます。ピンや一覧のコメントをクリックすると編集でき、一覧の×で削除できます。選択操作は元のページに伝わりません。注釈モード中はAIによるページ操作を停止しますが、`get_annotations` で保存済みの注釈を取得できます。注釈を付けた後は、チャットで「注釈を見て」と依頼してください。

注釈にはコメント、URL、範囲、要素のタグ・セレクター、画面サイズとスクロール位置を記録します。画像や入力値は自動取得しません。パスワード欄や1Passwordの表示に重なる選択、パスワード入力中の選択・保存は拒否します。注釈はページを隠しても保持し、ページ終了やブラウザ停止で破棄します。ページ遷移後も以前の注釈は取得できますが、`current: false` として区別し、ピンは表示しません。

永続プロファイルでは、右端の「1P」から1Passwordの公式Chrome拡張を導入できます。初回は1Passwordの案内タブを開き、以降のボタン操作は拡張自身が処理します。右クリックすると設定と更新を選べます。拡張とログイン情報はプロジェクトごとの保存領域に置かれ、普段使っているChromeとは共有しません。一時セッションでは拡張を利用できません。Macアプリとの連携を使わない場合は、拡張の設定でデスクトップアプリとの連携をオフにしてください。Touch ID連携は未検証です。

1Passwordを有効にした保存領域では、`evaluate_script` による任意JavaScript実行を禁止します。通常の取得・クリック・入力は既存の要素IDを使って続けられます。すでに任意JavaScriptを実行したセッションでは導入を拒否するため、すべてのページを終了して開き直してから導入してください。有効化による制限は再起動後も維持し、導入に失敗した場合も解除しません。

パスワード欄は取得情報から値と操作用IDを除外し、1Passwordの候補フレームは内容全体を除外します。対象は `type="password"` または `autocomplete="current-password"`／`new-password` の入力欄で、同じ文書内の表示切替後も保護を維持します。パスワード欄や候補フレームがある間は撮影を拒否し、入力済みパスワードがある間はページの取得・操作を拒否します。欄が消えるか空になると、URLが変わらなくても再開できます。取得中の対象変更を検出した場合も結果を返しません。

拡張画面と1Passwordドメインのページはユーザー専用とし、AIの一覧・取得・撮影・操作から除外します。ユーザー専用になったタブとその子タブは、そのままユーザー専用として保持します。ツールバーからのユーザー操作は利用できます。この保護はdozeのMCP操作に適用され、同じOSユーザーのシェルや別の画面撮影ツールを制限するものではありません。標準のパスワード属性を持たない独自の秘密入力欄は識別対象外です。

| 操作 | macOS | Linux |
| --- | --- | --- |
| URL編集 | ⌘L | Ctrl+L |
| 1〜8番目／最後の表示タブ | ⌘1〜8／⌘9 | Ctrl+1〜8／Ctrl+9 |
| 次／前の表示タブ | Control+Tab／Control+Shift+Tab、⌘⇧]／⌘⇧[ | Ctrl+Tab／Ctrl+Shift+Tab |
| 戻る／進む | ⌘[／⌘]、⌘←／⌘→ | Ctrl+[／Ctrl+]、Alt+←／Alt+→ |
| 再読み込み／キャッシュを無視して再読み込み | ⌘R／⌘⇧R | Ctrl+R／Ctrl+Shift+R、F5／Shift+F5 |
| 読み込み停止 | Esc | Esc |
| 拡大／縮小／元の倍率 | ⌘+／⌘−／⌘0 | Ctrl++／Ctrl+−／Ctrl+0 |
| 選択タブ／ウインドウを隠す | ⌘W／⌘⇧W | Ctrl+W／Ctrl+Shift+W |

タブの番号と巡回には「⋯」内の表示タブも含みます。×で隠したページは含みません。ダイアログ表示中は、タブ切替・非表示操作を除くブラウザショートカットを止め、Escはダイアログへの応答に使います。URL編集中のEscは編集を取り消します。

同じページでは利用者とAIが交代で操作してください。信号機の赤ボタンなどでウインドウを閉じても、表示だけを隠してページは保持します。各タブの×も表示から外すだけで、最後のタブを外すとウインドウを隠します。`show_page` で同じページを再表示できます。ページの終了はAI・システム側で管理し、`close_page` はページとその子ページを終了します。

ポップアップは開いたページの所有者を引き継ぎ、`list_pages` に表示されます。非表示のページから開いたポップアップも非表示を保ちます。表示中のページから開いたものは同じウインドウのタブとして表示され、タブ切替で元のページへ戻れます。`alert`・`confirm`・`prompt`は、非表示中はMCPから、表示中は画面内のダイアログから応答できます。`handle_dialog` の `prompt_text` で文字列を指定でき、省略時は初期値を使います。

サイトの権限要求は、非表示中は拒否し、表示中は共同操作画面で確認します。

撮影にはElectronの公開APIを使います。ページ全体の撮影中だけ描画領域を拡張し、撮影後にサイズとスクロール位置を戻します。OSのウインドウはリサイズしません。

ブラウザ制御は親子プロセス間の専用パイプで行い、デバッグ用TCPポートは開きません。サイトのページにはNode.jsを公開せず、操作用UIとは別の実行環境で扱います。

Electron内部のダイアログ処理を利用するため、実行部を45.3.1に固定しています。更新時は初回読み込み・子ページ・各ダイアログ・終了処理を再検証してください。Google OAuthなど、埋め込みブラウザを制限する認証方式は利用できない場合があります。詳細は[GoogleのOAuth方針](https://developers.google.com/identity/protocols/oauth2/policies)を確認してください。

## ログイン状態の保存

作業フォルダは、Codex固有の実験的な呼び出し情報 `codex/sandbox-state` の `sandboxCwd` から自動で取得します。Gitの補助情報 `workspaces` には依存しません。

| 作業フォルダ | 保存単位 |
| --- | --- |
| Git管理下 | 作業ツリーのルート。同じルート内の別フォルダや別プロジェクトも共有 |
| Git管理外 | 作業フォルダの実パス。フォルダごとに永続保存 |

同じフォルダへのシンボリックリンクは同じ保存領域を使います。別のチェックアウトとworktreeは別の保存領域になります。Git管理下の判定にはGitコマンドが必要です。最寄りの `.git` があるフォルダとGitが返したルートが一致しない場合は、保存済みのログイン状態を使わない一時環境で開き、起動結果に警告を添えます。一時環境は親スレッドと作業フォルダごとに分離し、その環境のすべてのタブを閉じると破棄します。元の保存データは変更しません。Gitの実行失敗など、それ以外の判定失敗はエラーにします。Git管理外ではGitコマンドを使いません。

プロファイルは `~/.config/doze-bworser-mcp/profiles/electron/<作業フォルダから算出したハッシュ>/` に保存します。旧Chromeのプロファイルは変更せず、移行後の初回利用では再ログインが必要です。Cookie、localStorage、IndexedDB等はタブ終了、タイムアウト、MCP切断、サービス再起動後も残ります。Electron標準では再起動後に消えるセッションCookieは、OSの暗号化機能で別途保存・復元します。期限を変更することはなく、ログアウトによる削除も反映します。安全な暗号化が使えない場合はエラーにし、平文保存へ切り替えません。以前のページや操作は自動で再実行しません。サービス側の失効・取り消しや、異常終了直前の未保存データによって再ログインが必要になる場合があります。

プロファイルには認証情報が含まれるため、Gitへの登録や公開をしないでください。Unixでは保存ディレクトリを所有者だけがアクセスできる権限にします。ログアウトは対象サイトで行います。保存データをすべて消す場合は、すべてのMCP接続を閉じ、`doze-bworser-mcp status` でサービスの終了を確認してから `profiles` ディレクトリを削除してください。

Codexから `sandboxCwd` を取得できない場合は `open_page` がエラーになります。対応するCodexへ更新し、このMCPへ再接続してください。作業フォルダの情報を提供しないCodex以外のクライアントは、接続ごとの一時保存領域を使い、永続化しません。

## インストール

```sh
brew install mmng-a/tap/doze-bworser-mcp
codex mcp add doze-bworser-mcp -- doze-bworser-mcp
```

HomebrewはRustで本体をビルドし、Node.jsと実行時の依存関係を配置します。初回の `open_page` で固定版Electronを公式の取得ライブラリからダウンロードします。普段使うブラウザには接続しません。

npmから導入する場合は、Node.js 22.12以降を用意して次を実行します。Rustは不要です。

```sh
npm install -g doze-bworser-mcp@0.2.0
codex mcp add doze-bworser-mcp -- doze-bworser-mcp
```

OSとCPUに合う実行ファイルはnpmが自動で選び、Electronは初回利用時に取得します。コマンドの導入にはHomebrewかnpmのどちらかを使ってください。

MCPクライアントが実行ファイルを見つけられない場合は、`command -v doze-bworser-mcp`（PowerShellでは `(Get-Command doze-bworser-mcp).Source`）で確認した絶対パスを登録してください。MCP設定を直接書く場合は次のとおりです。

```toml
[mcp_servers.doze-bworser-mcp]
command = "doze-bworser-mcp"
tool_timeout_sec = 90
```

専用インストーラーやフック登録は不要です。MCPサーバーはクライアントの設定ファイルを書き換えません。ローカル通信の認証情報は初回起動時に `~/.config/doze-bworser-mcp`、専用ブラウザは `~/.cache/doze-bworser-mcp` に準備します。設定ファイルを公開しないでください。初回のブラウザ取得には時間がかかることがあります。

更新前に、このサーバーへのすべてのMCP接続を閉じ、`doze-bworser-mcp status` で共有サービスが終了したことを確認してください。その後、導入方法に合わせて `brew upgrade mmng-a/tap/doze-bworser-mcp` または `npm install -g doze-bworser-mcp@0.2.0` を実行し、再接続します。`doze-bworser-mcp status` で共有サービスの状態を確認できます。

macOSとLinuxではHomebrewを利用できます。npm版はWindows x64にも対応しています。ソースからビルドする場合は、Rust 1.89以降、Node.js 22.12以降とnpmが必要です。

```sh
npm ci --ignore-scripts --prefix runtime
DOZE_RUNTIME_DIR="$PWD/runtime" cargo build --release --locked
codex mcp add doze-bworser-mcp -- /absolute/path/to/target/release/doze-bworser-mcp
```

ソースからのビルドでは、上記の `DOZE_RUNTIME_DIR` で実行部の場所を明示します。Homebrew版とnpm配布物は自動で指定します。WindowsのPowerShellでビルドする場合は、先に `$env:DOZE_RUNTIME_DIR = (Resolve-Path runtime).Path` を設定し、`cargo build --release --locked` を実行してください。

npm版の対応環境と、配布物の作成・検証手順は [npm/README.md](https://github.com/mmng-a/doze-bworser-mcp/blob/main/npm/README.md) に記載しています。

MCPにしてもOSの制限やツールの承認はなくなりません。MCPプロセス自体を制限するホストでは、ローカルIPC、ブラウザのダウンロード・起動への許可が必要です。

## ツール

| ツール | 引数 | 結果 |
| --- | --- | --- |
| `open_page` | `url`、任意の `headed` | `{ "page_id": "…" }` |
| `show_page` | `page_id` | 既存ページの共同操作画面を表示して `OK` |
| `list_pages` | なし | 自分のタブのID・URL・タイトル |
| `inspect_page` | `page_id` | `uid` 付きのDevTools形式のテキスト |
| `get_annotations` | `page_id` | ユーザーが保存した注釈のコメント・場所・URL |
| `navigate_page` | `page_id`、`url` | DOMの準備後に `OK` |
| `click` | `page_id`、`element` | `OK` |
| `fill` | `page_id`、`element`、`value` | `OK` |
| `press_key` | `page_id`、`key` | `OK` |
| `scroll_page` | `page_id`、`y`、任意の `x` | `OK` |
| `set_viewport` | `page_id`、`width`、`height` | `OK` |
| `take_screenshot` | `page_id`、任意の `full_page` | PNG画像 |
| `evaluate_script` | `page_id`、`expression` | Promiseの完了を待ってJSONの値 |
| `handle_dialog` | `page_id`、`accept`、任意の `prompt_text` | 中断した操作の完了後に `OK`、または次のダイアログ |
| `close_page` | `page_id` | 終了後に `OK` |

結果はMCPの `content` だけで返します。`open_page` は先頭のテキスト項目に `{ "page_id": "…" }` を返し、一時環境へ切り替えた場合は別のテキスト項目に警告を返します。警告は利用者に伝えてください。URLはHTTP(S)か `about:blank` に限定します。公開スキーマと引数の検証は、公式MCP SDKを通じて同じZod定義から生成します。真偽値に文字列の `"false"` は使えません。

要素の操作には、最新の `inspect_page` が返す `uid` を使ってください。HTMLの選択肢はPuppeteerの選択APIで操作し、無効な選択肢や値が重複して一意に選べない場合はエラーにします。独自の選択UIは通常のクリックを使います。画面は1200×900で開きます。ビューポートの変更では利用者のウインドウをリサイズしません。画面表示は明示された共同操作にだけ使います。成果物の作成に正式な撮影・検査CLIがある場合はそちらを優先します。

## 動作と後始末

- 所有者と作業フォルダはCodexの呼び出し情報から取得し、モデルが入力する引数にはしません。保存領域を共有していても、他のスレッドのタブは操作できません。切断時にはその接続のタブを閉じます。
- 30分以上操作していないタブは、ダイアログの応答待ちも含めて終了します。実行中の操作には別の制限時間を適用します。古いページIDは再利用しません。終了後は新しいタブを開いてください。
- 順番待ちと実行の制限時間は、それぞれ既定で20秒です。起動と一覧取得にも制限時間を適用します。ダイアログの応答待ちはPuppeteer内部の別の制限時間では打ち切りません。待機中に取り消された要求や時間切れの要求は実行しません。実行中の取消・時間切れでは、結果が不明なタブを閉じます。外部への変更が起きている可能性は残ります。`beforeunload`で離脱を止めるページは保持し、遷移をエラーとして返します。この離脱確認をMCPから承認する動作には対応していません。自動再実行はしません。
- ダイアログの通知を返しても、元の操作の順番は解放しません。元の操作を追跡し、応答待ちでは実行の制限時間を止め、通常操作との重複を防ぎます。`handle_dialog` は元の操作を再開して完了を待ちます。`open_page` 中に開いた場合は、保持した `page_id` をエラーに含めます。
- `close_page` は実行中の操作を中断します。終了を始める前の取消ではタブを保持し、終了を始めた後は完了まで続けます。タブの割当を安全に取り消せない場合や、後始末が停止した場合は、その専用ブラウザを強制終了し、同じブラウザの他のタブも失われます。
- プロジェクトの最後のタブを閉じると対応するElectronを終了し、プロファイルは残します。Codex以外のクライアントが使う一時プロファイルは削除します。MCP接続中はNodeが残り、最後の切断後に終了します。NodeやElectronの異常終了時にはページが失われるため、再接続して新しく開いてください。開始済みの操作は再実行しません。MCP転送前の接続切断・終了中通知だけは、10秒以内で再接続します。認証不一致や開始済みのMCP要求は再送しません。
- 入力操作の成功は、外部の業務処理の成功を保証しません。必要に応じて操作後の画面で結果を確認してください。

アクセシビリティ情報の整形には、Apache-2.0のChrome DevTools MCP由来のコードを使用しています。ライセンスと出典は`runtime/vendor`に保持しています。

## Git運用

- `dev`は通常の開発、`main`は配布対象の確定コードを管理します。
- 変更の反映経路は`dev → main`とします。

## 検証とCI

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
npm ci --ignore-scripts --prefix runtime
npm test --prefix runtime
DOZE_BROWSER_ELECTRON='/Electron実行ファイルの絶対パス' DOZE_TEST_VIEWER=1 cargo test --locked --test service
```

通常のテストではElectronを起動せず、ページの所有者、並行処理、取消、ダイアログ待機、保存領域を確認します。`DOZE_BROWSER_ELECTRON` に実行ファイルを指定する実ブラウザ検証では、ローカルページで入力・内容取得・撮影・ポップアップ・ダイアログ・保存状態・終了処理を確認します。`DOZE_TEST_VIEWER=1` を追加すると、共同操作画面のURL移動・入力・非表示切替も確認します。画面表示が可能な環境が必要です。macOSの共同操作UIテストは既定で非アクティブ表示にし、ウインドウへのフォーカス移動も拒否します。前面表示を検証する場合だけ `DOZE_TEST_BACKGROUND=0` を指定してください。これはテスト専用の起動処理で、通常の共同操作画面には適用しません。OSでの実キー入力によるアクセラレータ確認は別途必要です。Windowsでの新構成の動作は未検証です。

Linuxで新構成を動かすには、画面セッションと、OS暗号化に使うSecret Service（GNOME Keyring等）が必要です。CIでは仮想画面と一時キーチェーンを準備します。ZIP展開はNode 24以降との互換性のため`yauzl`を3.4.0に固定しています。展開対象は公式Electron配布物に限定し、取得ライブラリでチェックサムを検証します。

CIは「Run workflow」または `gh workflow run ci.yml -f os=ubuntu-latest -f suite=browser` で手動実行した場合だけ動作します。実行ごとにLinux・Windows・macOSから対象を選びます。pushとプルリクエストでは起動しません。npm配布物の作成・導入検証は、別の手動ワークフロー `npm-packages.yml` で4種類のOS・CPUに対して行い、npmへは公開しません。対象のOSに加え、通常の `light` と、固定版Electronの取得・実ブラウザ・共同操作画面の検証を加えた `browser` を選べます。選んだOSで整形、Clippy、Rust、Nodeを検証します。デプロイやサービスのインストールは行いません。
